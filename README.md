# STM32HAL CMake C++ Template

[中文](README-zh_CN.md) | English

Use this directory with a CMake project generated by STM32CubeMX. The `applications` sources can be copied independently; copy `bsp` when the board delay module is needed.

## Directory structure and header includes

User code is organized by functional module. Keep each module's `.cpp` and `.hpp` files (or `.c` and `.h` files) in the same directory:

```text
applications/
└── main/
    ├── cpp_interface.cpp
    └── cpp_interface.h
bsp/
└── boards/
    ├── common/
    │   └── struct_typedef.h
    └── delay/
        ├── bsp_delay.cpp
        └── bsp_delay.hpp
cmake/
└── user/
    └── CMakeLists.txt
```

`cmake/user/CMakeLists.txt` adds `applications` and `bsp/boards` to the target's header search paths. Include headers using a `module/header` path relative to either directory:

```cpp
#include "main/cpp_interface.h"
#include "delay/bsp_delay.hpp"
#include "common/struct_typedef.h"
```

New modules under these two directories can use the same convention without adding a separate header search path for each module. Keep the existing structure of CubeMX-generated directories such as `Core` and `Drivers`.

## Setup

1. In the generated root `CMakeLists.txt`, keep the existing C standard settings and add the C++ standard settings before `project()`:

```cmake
# Setup compiler settings
set(CMAKE_C_STANDARD 11 CACHE STRING "C language standard")
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS ON)

set(CMAKE_CXX_STANDARD 20 CACHE STRING "C++ language standard")
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS ON)
```

`CACHE STRING` makes the standard an overridable build setting. An existing build directory retains its cached value when the default above changes. With GCC, `*_EXTENSIONS ON` normally selects the `gnu11` / `gnu++20` dialects; `OFF` requests `c11` / `c++20`. Keeping `C_EXTENSIONS ON` is a practical choice for CubeMX-generated C code. If your C++ code does not use GNU-specific syntax, you can set `CXX_EXTENSIONS` to `OFF`.

2. Copy `cmake/user`, `applications`, and `bsp`. **Add `cmake/user` to the top-level `CMakeLists.txt`**, preferably after the CubeMX subdirectory:

```cmake
# Add STM32CubeMX generated sources
add_subdirectory(cmake/stm32cubemx)

# Add USER generated sources
add_subdirectory(cmake/user)
```

The generated `project(${CMAKE_PROJECT_NAME})` does not restrict languages, so CMake enables C and C++ by default. `enable_language(C ASM)` does not disable C++, and does not need changing. If a future `project()` explicitly specifies `LANGUAGES C ASM`, add `CXX` to that list.

To use only the application entry point, omit `bsp` and remove the `Bsp_Boards_Src` definition, its reference in `target_sources()`, and the `bsp/boards` header search path from `cmake/user/CMakeLists.txt`.

3. Add each new `.c` or `.cpp` file path manually to the appropriate `Applications_Src` or `Bsp_Boards_Src` list in `cmake/user/CMakeLists.txt`. For example, for a new `bsp/boards/led/bsp_led.cpp`, add `${CMAKE_CURRENT_SOURCE_DIR}/../../bsp/boards/led/bsp_led.cpp` to `Bsp_Boards_Src`. `.h` and `.hpp` files do not need to be listed as compilation sources.

4. Include the application entry point in the header `USER CODE` section of CubeMX's `main.c` or another C file:

```c
#include "main/cpp_interface.h"
```

Call `cpp_main()` from the appropriate `USER CODE` section. `applications/main/cpp_interface.h` uses `extern "C"` to expose the interface to C files. `isRTOS` defaults to `0` in that header, so `cpp_main()` enters an infinite loop. For FreeRTOS projects, set it to `1` and choose an appropriate call site.

5. `bsp_delay` uses the Cortex-M3/M4 DWT cycle counter. Call `Init(sysclk)` after clock setup, with the clock frequency in MHz. The delay is a busy wait; it does not change SysTick or override HAL's `HAL_Delay`.

## Cleanup script

`clean.bash` always operates on the directory containing the script. Running it without arguments only previews the removal list; `./clean.bash --apply` performs the deletion. It removes top-level files outside its keep list, including CubeMX-generated `Core`, `Drivers`, `CMakeLists.txt`, build output, and IDE settings. It keeps `applications`, `bsp`, `cmake/user`, and root `.ioc` files.
